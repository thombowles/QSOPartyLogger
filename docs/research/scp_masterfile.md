# MASTER.SCP — super check partial database

**Source:** `https://www.supercheckpartial.com/MASTER.SCP` — the Super
Check Partial project's distribution site. Observed 2026-08-04.

## Server behavior (what `SCPClient` is built against)

- Valid TLS via BunnyCDN — plain HTTPS, no ATS exception needed.
- HEAD answers with `Last-Modified: Fri, 31 Jul 2026 00:03:08 GMT`,
  `Content-Length: 359507`, and an `ETag`. `Last-Modified`'s date equals
  the file's own `# Release 2026.07.31` stamp, so a HEAD can judge
  freshness without the body — the cty.dat situation exactly.
- `Cache-Control: public, max-age=21600` — a CDN in front of a file that
  changes every few weeks.

## File shape (fetched 2026-08-04, release 2026.07.31)

    !!Order,1,1
    #
    # Super Check Partial
    # Release 2026.07.31
    # Generated by bb-scp
    #
    2D0OMN
    2E0AOZ
    …
    ZZ7ZZ

- 50,027 lines, CRLF-terminated; six of them the directive and comments,
  so **50,021 calls** — counted by the parser's own rules over the file the
  app downloaded (`2026-08-05`), with no duplicates dropped.
- Calls are uppercase `[A-Z0-9/]`, three characters or longer.
- The `!!Order,1,1` directive and `#` comments are the only non-call
  lines; `SCPDatabase.parse` drops anything that does not scan as a call,
  so neither needs a special case.

## Reliability, measured 2026-08-05

The host is **not dependable**, and the client's failure posture is sized to
that rather than to a hypothetical. Measured directly against the real
network (no proxy), four HEAD requests in a row alternated cleanly:

    HEAD  timeout at 25 s
    HEAD  200 in 7.08 s
    HEAD  timeout at 25 s
    HEAD  200 in 7.07 s
    GET   200 in 32.25 s   (359,507 B — about 11 KB/s)

GET fails as often as HEAD, so it is neither method-specific nor ours: the
same URLSession HEAD against country-files.com answered in **0.15 s** the
same minute. Responses carry `cdn-cache: STALE`, so BunnyCDN is serving an
aged copy while trying to revalidate against an origin that is not
answering.

Consequences the code already takes:

- **No retry.** Hammering a struggling volunteer origin is the wrong
  instinct, and a Refresh that retried would just make the operator wait
  through two timeouts instead of one.
- **A failed check is not a broken feature**, and the message says so —
  naming the host and the number of cached calls still in service.
- **The throttle clock is not advanced on failure**, so a bad afternoon
  does not cost a day's worth of checking; the next launch tries again.

## Standing

**Hint data, never authority** (constitution Article 1): the file is a
community distillation of submitted contest logs. Nothing from it reaches
scoring, validation, or export — it draws the strip of known calls under
the entry row, and that is all.

The file is deliberately not bundled (the call history precedent):
`SCPClient` downloads it on first launch and re-checks daily by HEAD,
so the season never starts on a committed copy that has aged.
